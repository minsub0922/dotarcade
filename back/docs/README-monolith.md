# 🕹️ DOTCADE — 멀티에이전트 게임 스튜디오 & 오락실 운영 시뮬레이션

당신은 도트 게임 스튜디오의 **팀장**입니다. 메타버스 사무실에서 AI 팀원 5명과 **BMAD Method 회의**로 *실제로 동작하는* 도트 게임을 만들고, 오락실에 배포해 **20명의 AI 손님**에게 실플레이 평가를 받으세요. 피드백을 반영한 업그레이드 회의로 게임을 키워나가는 운영 시뮬레이션입니다.

> 프로젝트 자체도 BMAD Method로 제작되었습니다 — `docs/`(브리프·PRD·아키텍처·스토리), `_bmad/`(BMAD v6 설치본, `npx bmad-method install`) 참고.

---

## 🚀 빠른 시작

```bash
# 요구사항: Node 20+, git, (선택) Python3+Pillow — 에셋 재생성 시에만
npm install
npm run dev        # 개발: 서버(5175) + Vite(5173) → http://localhost:5173
# 또는
npm run build && npm start   # 프로덕션: http://localhost:5175 하나로 서빙
```

**Gemini API 키**는 루트 `.env`에 이미 설정되어 있습니다 (요청하신 키 반영됨).

```env
GEMINI_API_KEY=...            # https://aistudio.google.com/apikey
GEMINI_MODEL_SMART=gemini-3.6-flash        # 코드/문서 생성
GEMINI_MODEL_FAST=gemini-3.5-flash-lite    # 토론/피드백/대화
MAX_LLM_CONCURRENCY=4         # 무료 키는 3~4 권장
LLM_MODE=auto                 # auto | live | mock
```

부팅 시 Gemini 도달성을 자동 감지합니다. 인터넷/키 문제가 있으면 **모의(mock) 모드**로 전환되어 전체 기능을 오프라인 데모로 체험할 수 있습니다 (우측 상단 배지로 표시, 설정에서 재감지 가능).

## 🎮 사용법

| 조작 | 기능 |
|---|---|
| 방향키 / WASD | 팀장 캐릭터 이동 |
| **E** (또는 Enter) | 상호작용 — 팀원 1:1 대화 · 게임팩 진열대 · 오락실 문 |
| ESC | 패널 닫기 |

### 제작 루프
1. **📋 회의 시작** — 안건 입력 (예: "슬라임이 별을 받는 게임"). 팀원 5명이 회의실에 착석하고 BMAD 파이프라인이 실시간으로 진행됩니다:
   `리서치(웹검색+RAG 개별 수행) → 컨셉 토론(멀티에이전트 디베이트 2R) → PRD(PM) → 아트/UX(디자이너) → 아키텍처(개발1) → 팀장 승인 → 구현(개발2) → 자동 QA(샌드박스 봇 테스트+수리 루프) → 릴리즈(git 태그)`
   - 승인 게이트에서 추가 요구사항을 입력하면 PRD에 반영됩니다 (설정에서 자동 진행 ON/OFF)
2. **🗄️ 게임팩** — 플레이 / **git 코드 뷰어** / 버전 로그·diff / 공유 링크 / 업그레이드 회의 / 오락실 배포
3. **🕹️ 오락실 배포** — 20명의 손님(11세~57세 페르소나)이 입장해 캐비닛에서 **실제 봇 플레이**(좌측 하단 LIVE 화면) + 코드 분석 후 점수(1~10)와 상세 피드백을 남깁니다. 병렬 처리로 수 분 내 완료(10분 상한, 전원 완료 시 조기 종료) → 종합 리포트 저장
4. **⬆️ 업그레이드 회의** — 피드백이 RAG와 회의 컨텍스트에 자동 반영 → 버전 업(v1.1.0…) + CHANGELOG + git diff

### 게임 공유
각 게임은 공개 링크로 즉시 플레이 가능합니다: `http://<호스트>:5175/play/<게임id>` (모바일 터치 컨트롤 자동 표시). 라이브러리 → 🔗 공유 링크 복사.

## 🧠 멀티에이전트 구성

**사무실 팀 (BMAD 역할 매핑)**
- 박서준 (PM) → PRD · 릴리즈 노트
- 이도현 (시니어 개발) → 아키텍처 · QA
- 정우진 (주니어 개발) → 구현(코드 생성) · 수리
- 김다은 (디자이너) → 아트/UX 스펙
- 한지민 (작가) → 리서치 · 컨셉

토론은 **공유 트랜스크립트**로 진행되고, 리서치(웹검색 grounding + RAG)는 **에이전트별 비공유 컨텍스트**로 수행됩니다. 과거 게임 PRD·오락실 피드백은 서버 RAG(임베딩 검색)에 적재되어 다음 회의에 인용됩니다.

**오락실 손님 20명** — 초등학생부터 은퇴자까지 서로 다른 페르소나·평가 기준·플레이 성향(봇 파라미터)을 가지며, 전원이 병렬 파이프라인으로 처리됩니다.

## 🏗️ 아키텍처 (요약)

```
.env ← Gemini 키 (서버 전용)
server/  Express — Gemini 프록시(스트리밍·검색·임베딩·모델 폴백·백오프·세마포어)
         게임별 실제 git 레포(커밋·태그·show·diff) · JSON DB · RAG · /play/:id 공유 플레이어
web/     React+zustand UI · 캔버스 월드 엔진(A*·FSM·말풍선) · 회의 오케스트레이터
         게임팩 하네스(샌드박스 iframe, 봇 자동 플레이·텔레메트리) · 오락실 시뮬 파이프라인
```

- 생성 게임은 **게임팩 계약**(`window.game = {meta, start(canvas, api), stop()}`)을 따르며 `sandbox` iframe에서만 실행됩니다.
- 게임 레포 위치: `server/data/games/<게임id>` — 실제 git 저장소입니다 (`git log`, `git tag` 확인 가능).
- 상세 설계: `docs/architecture.md`

## 🔧 트러블슈팅

- **모의 모드로 떠요** → 인터넷/키 확인 후 설정 → "연결 다시 감지" 또는 서버 재시작. `.env`의 `LLM_MODE=live`로 강제 가능.
- **429 (쿼터 초과)** → 무료 키의 분당 한도입니다. 자동 백오프+모델 폴백이 동작하지만, `.env`의 `MAX_LLM_CONCURRENCY=2`, 설정의 동시 시뮬레이션 수 ↓ 권장.
- **모델 404** → `.env` 모델명을 최신으로 교체 (자동 폴백 체인: 3.6-flash → 3.5-flash → 3.5-flash-lite → 2.5-flash → flash-latest).
- **데이터 초기화** → 서버 종료 후 `server/data/` 삭제 (기본 게임 3종은 다시 시드됨).
- **에셋 재생성** → `npm run seed:assets` (Python3 + Pillow 필요, 원본 시트 경로는 tools/ 스크립트 상단 수정).
