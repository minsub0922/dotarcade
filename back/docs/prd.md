# PRD — DOTCADE

> BMAD Method · Phase 2 (PM) 산출물

## 1. 목표
동작하는 도트 게임을 산출하는 멀티에이전트 스튜디오 시뮬레이션 웹앱. 두 개의 맵(사무실/오락실), 하나의 제작 루프(회의→게임팩→배포→피드백→업그레이드).

## 2. 기능 요구사항 (FR)

### FR1 — 메타버스 사무실 (맵 1)
- 게더타운 스타일 탑뷰 타일맵 (30×20, 48px)
- 캐릭터 6: 팀장(플레이어), PM 박서준, 개발 이도현, 개발 정우진, 디자이너 김다은, 작가 한지민
- 플레이어: 방향키/WASD 이동, 충돌 처리. 에이전트: 자리 착석 + 자율 배회 + 경로이동(A*)
- 상호작용(E키): 에이전트 → 1:1 대화 / 게임팩 진열대 → 라이브러리 / ARCADE 문 → 오락실

### FR2 — 1:1 대화
- 페르소나 시스템 프롬프트 + 스튜디오 컨텍스트(게임 목록·최근 회의·피드백 요약) + 대화 이력
- 스트리밍 응답, 말풍선 + 사이드 패널 동시 표시, 서버에 이력 저장

### FR3 — 회의 시뮬레이션 (BMAD 파이프라인)
- 팀장이 안건 입력 → 팀원들이 회의실로 걸어와 착석 → 단계별 진행이 실시간 가시화
- 단계: ①킥오프 ②리서치(에이전트별 웹검색+RAG **개별** 수행, 컨텍스트 비공유) ③컨셉 토론 2라운드(공유 컨텍스트 멀티에이전트 디베이트) ④PRD(PM) ⑤아트/UX 스펙(디자이너) ⑥아키텍처(개발1) ⑦팀장 승인 게이트 ⑧구현(개발2, 코드 생성) ⑨QA(자동 하네스 스모크 테스트 + 수리 루프 ≤2회) ⑩릴리즈(체인지로그·버전 태그)
- 산출물: 실행 가능한 game.js + PRD/디자인/아키텍처 문서 + CHANGELOG → git 레포 커밋·태그
- 기존 게임팩 선택 시 업그레이드 회의(기존 코드+피드백 컨텍스트, 버전 증가)

### FR4 — 게임팩 시스템
- 게임팩 계약: `window.game = { meta{title,desc,controls,viewport}, start(canvas,api), stop() }`, `api.reportScore/gameOver/rng`
- 샌드박스 iframe(allow-scripts) 하네스: 실행·점수 수집·에러 캡처·봇 자동 플레이
- 라이브러리 UI: 목록/상세(플레이·코드 뷰어·버전 로그·diff·공유 링크·업그레이드 회의·오락실 배포)
- 각 게임 = 서버의 실제 git 레포 (커밋/태그), 웹에서 파일·diff 열람
- 공유: `/play/:id` 공개 링크 (모바일 터치 컨트롤 포함)
- 기본 게임 3종 사전 제작: 픽셀 러너(공룡류)/메테오 닷지/스네이크

### FR5 — 오락실 시뮬레이션 (맵 2)
- 배포 시 오락실 맵 활성화, 20명 손님 에이전트 입장(10대~50대 페르소나)
- 유저 조작 없는 관전 모드: 손님이 캐비닛으로 이동해 플레이하는 모습 가시화
- 실제 검증: ①숨김 iframe 봇 플레이(페르소나별 플레이 성향·시간) → 텔레메트리 ②코드·기획 분석 ③페르소나 LLM 피드백 JSON(점수 1~10, 한줄평, 상세, 버그, 제안)
- 병렬 처리(동시 시뮬 4, LLM 큐)로 10분 내 완료, 전원 완료 시 조기종료 → 종합 리포트(평균·분포·개선 우선순위)
- 피드백은 버전별로 저장, RAG에 적재되어 다음 회의에서 인용됨

### FR6 — 운영/설정
- 서버 .env: GEMINI_API_KEY, 모델(smart/fast), 동시성. 설정 UI: 모델 오버라이드, 자동 진행, LLM 상태(live/mock) 표시
- LLM 도달 불가 시 모의(mock) 모드 자동 전환(배지 표시) — 전체 파이프라인 오프라인 데모 가능

## 3. 비기능 요구사항
- 회의 1회 LLM 호출 ≤ 25회, 오락실 시뮬 ≤ 25회 (요약 포함)
- 생성 게임: 외부 리소스/네트워크 금지, 단일 파일, 캔버스 픽셀아트
- 서버 재시작 후에도 데이터 유지 (JSON DB + git 레포)

## 4. 아웃 오브 스코프
멀티플레이어, 로그인, 과금, 모바일 네이티브, 게임 내 오디오 필수화
